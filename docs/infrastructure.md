# Phase 1: infrastructure (in this order)

1. **Dataset schema and normalization** (see `datasets.md`).
2. **Server launch and teardown.** Simple scripts to bring up and shut down named sets of servers,
   including Maya Q1 and Q2 and the ComfyUI workers. Enforce the GPU rules in `rig.md`. The proxy calls
   these.
3. **Proxy.** Routes requests to all model servers by model name and applies the scheduling rules. If
   the model is not loaded: queue, group by model, start once, drain. Reuse existing proxy code in the
   repo if present.
4. **Activation capture** (HF transformers, LLMs only; see policy below).
5. **Dataset run workflow** that does not depend on inference: manifest driven, resumable, replayable
   from cached model outputs, writes a run manifest with scores per stage.
6. **Dashboard** (`dashboard.md`), starting with run history and the queue view once manifests exist.

## Activation capture policy (storage is limited)

- Save per prompt: last-token and mean-pooled hidden states, every 3rd layer, fp16. Per-token states
  only for a small sampled subset.
- Shard files keyed by prompt id with an index. Record model hash, tokenizer version, layer list and
  dtype with each shard. Activations from a different checkpoint are not comparable.
- Check free space before a run and stop at a configured limit.
- Sizing: ~180 KB per prompt per position across all layers at fp16 for a 4B-class model.

## Current milestone: end-to-end v0

Done when one iteration runs unattended and its scores show on the dashboard; low scores are fine:
approved public data (reports/2026-11-04-dataset-approvals.md), normalized with family splits ->
deterministic stages (normalize, regex/NLP) and one model stage -> replay run manifest -> dashboard
metrics. A scheduled job repeats it, adding red-team items generated by Maya and approved by the evaluator.

Constraints:
- **GPUs.** Maya holds GPUs 2-6 and stays up (stopping it needs the user's approval); 0-1 are
  reserved. Maya is the inference engine serving GLM 5.3 flash, not a decision model: GLM stages
  (red-team generation) call it through its OpenAI-style chat API (concurrency 1, every output
  cached). Models of 4B or less run on CPU-only llama.cpp (about 10 GB RAM is free).
- **Disk.** Raw data, normalized data and caches live under `/mnt/storage/llm_security/` (10 GB
  budget); `data/` in the repo stays small.
- **Agent budget.** Claude and Codex are on small plans. Bulk work (generation, labeling,
  classification) runs on local models from scripts, never through an agent.
- **Evaluator.** CPU llama.cpp with a model from the inventory that is not GLM-family.

Order: loaders and splits -> rule stage score cache -> dashboard metrics views -> Maya client with
queue and cache (no lifecycle actions on Maya) and a model stage -> red-team generator and evaluator
-> `ops/iterate.py`, run on a schedule by the dispatcher without agent tokens.
